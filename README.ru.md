# u5g-monitor (кратко по-русски)

Стек для мониторинга UniFi 5G Max Outdoor (DNA) и автоматического «лечения» провалов скорости.
Лечение = переключение профиля диапазонов модема `00 → 0D → 00` (повторная регистрация ~2 мин, без реального обрыва).

1. `./scripts/init.sh` — создаст `.env` (впиши Telegram, ключ UniFi API, пароль Grafana), повтори запуск.
2. `modem/install-modem.sh <ssh_user>@<IP модема>` — поставит на модем диспетчер и ограниченный ключ (ключ умеет только `ping`, `diag`, `cure`).
3. `docker compose up -d`.

- Режим по умолчанию **dry**: эпизоды находятся и диагностируются, модем не трогается.
  Включить лечение: `echo live > data/mode`. Вернуть: `echo dry > data/mode`.
- Лечение требует **кастомного профиля `0D`** («No n28 Test»), которого нет в стандартном наборе модема. Если его нет, `cure` откажется работать и ничего не изменит; после лечения модем всегда возвращается в профиль `00`. Подробности: `docs/MODEM.md`.
- Каждую минуту лёгкая проба скачивает 1 МБ с `nopeus.dna.fi`. Эпизод = три пробы подряд дольше порога: 2 × baseline (медиана хорошего состояния за ~24 ч), не меньше 0,8 с; конец = пять быстрых подряд. Обнаружение через 2-3 минуты. Срабатывание не чаще раза в 3 часа, не больше 4 в сутки.
- Установка на TrueNAS: `docs/TRUENAS.md`. Что известно о причине проблемы: `docs/FINDINGS.md`. Что не вошло в репозиторий: `docs/KNOWN_GAPS.md`.
- После перезагрузки модема диспетчер, ключ и порт 2222 пропадают (во флеш ничего не пишем) — придёт алерт «modem unreachable»;
  повтори шаг 2.
